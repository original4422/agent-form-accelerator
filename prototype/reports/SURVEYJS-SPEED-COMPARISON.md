# SurveyJS 报销流程端到端对照（2026-09-30）

## 测量协议

比较同一页 SurveyJS 3.1.2 报销应用的两种 Codex 接口：生产来源绑定工具，以及官方 `@playwright/mcp` 0.0.82 的完整浏览器工具（包含脚本执行）。官方适配层只在脚本第二个参数提供相同的未映射源事实，并预取公开页面快照；不提供填表脚本、字段映射或定位器。两边得到同一任务提示与源事实，初始观察分别采用接口自己的公开表示。

固定 Codex CLI 0.155.1、`gpt-6-sol`、low reasoning，每次使用新 Chromium profile、空服务器草稿和临时会话。rail、car 每种方法各两次，共八次；第一轮 rail 先官方、car 先绑定，第二轮反向。每个模型任务上限 240 秒；失败和恢复均保留，不挑成功样本重跑。任务串行执行，期间不运行本地推理压力测试。

主指标是启动 Codex 到进程结束的完整耗时，包含模型推理、工具执行及最终回复。`setupMs` 单独记录服务构建、浏览器和工具预取；`totalMs` 还包括模型结束后的独立验收和刷新，不等同于模型耗时。逐个工具调用时间与 token 使用量随 JSON 保存。

共同验收：服务器全部来源值与预期一致、服务器金额正确、无在途保存、零提交、页面公开保存状态与金额正确、刷新后全部公开字段值恢复。来源绑定覆盖独立报告；官方接口没有来源台账，不将其标记为“已验证绑定”。分支变化后，提示同时要求两边重新核对全部值；绑定接口若清空台账，则显式重新绑定失效来源。生产执行器和业务应用没有为本次对照修改。

## 测前检查

- 8 项原生选择控件检查、两条完整绑定流程通过。
- 两条官方脚本流程独立核验服务器值、金额与刷新恢复通过；脚本仅用于确定性可达检查，不提供给模型。
- 准备时 `getByLabel('Employee name', {exact:true})` 未解析 SurveyJS 控件，30 秒超时。改用公开 role/name 与唯一日期输入后通过，记录在 [预检失败](expense-baseline-preflight-failure.json)。这是测前测试脚本的失败，未调用模型，未改变应用。

## 实测结果

固定批次 [1790712610965](codex-expense-comparison-1790712610965.json) 八次全部通过共同业务验收；四次绑定任务的来源覆盖也全部通过。生产运行文件及依赖共 39 项指纹在批次前后完全一致。

| 轮次 / 分支 | 官方完整秒数 / 调用 | 绑定完整秒数 / 调用 | 官方失败工具秒数 | 绑定来源条目 / 必填覆盖 |
|---|---:|---:|---:|---|
| 1 / Rail | 117.56 / 4 | 45.69 / 3 | 68.17 | 6 / 5 个必填全覆盖 |
| 1 / Car | 115.00 / 5 | 42.73 / 2 | 56.62 | 8 / 7 个必填全覆盖 |
| 2 / Rail | 126.30 / 5 | 33.97 / 2 | 72.96 | 6 / 5 个必填全覆盖 |
| 2 / Car | 88.62 / 3 | 40.14 / 3 | 34.67 | 8 / 7 个必填全覆盖 |

官方完整耗时中位数 **116.28 秒**，绑定 **41.44 秒**。每次绑定均有两次实际 `form_apply_bindings`；两个三调用样本还包含只读工具查询。所有服务端来源值、GBP 42.75 / 50.45 金额、保存完成和刷新恢复均正确，提交次数为零。官方工具没有来源台账，表中的覆盖数仅属于绑定接口。

**本批四次官方任务都发生局部超时并自行恢复，没有无失败的官方样本。** 全部先调用 radio `.check()`，被 SurveyJS 装饰 SVG 拦住，各等待 30 秒后改点可见标签。其余三次错误分别是把 status 文本当 accessible name、日期输入后 Tab 仍未离开字段导致保存等待超时、将新增数值输入误判为 textbox。错误摘要及分项耗时见 [逐次诊断](expense-comparison-summary.json)。原始失败不删除，没有追加采样替换结果。

因此，这组数据证明当前接口在该工作流上更快完成了任务，并体现出已实现的控件适配、失焦保存与动态回执的价值；它不能单独证明把同一套正确动作批量化就有上述幅度的收益。官方工具执行中位 73.92 秒，绑定 12.12 秒，大量差距是官方恢复成本。不能从实测耗时中直接减掉失败秒数来制造一个“无失败基线”，因为恢复也改变了后续观察、脚本和模型决策。原先三种完整真实实现稳定 2× 的验收条件仍未满足。

公开源文档和提示在所有对应任务一致；私有轨迹复核未出现隐藏模型状态、直接业务 API、强制点击或提交。分支出现后四次绑定均显式重新绑定选中的交通方式，没有修改生产台账自动失效契约。

测后只改 runner 的 CLI 版本记录为实时读取，避免未来复现仍写死本次版本；原计时 runner 保存在 [测量源码](source-snapshots/expense-comparison-measured/codex-expense-comparison.mjs)，JSON 的 `postMeasurementArchives` 给出映射，39 项哈希逐项复核一致。没有借元数据修正追加模型测试。

## 复现

```bash
npm run check:expense
npm run bench:expense:compare
```

后一命令使用当前 Codex 登录运行固定八次任务；编号报告保留逐次结果，原始模型轨迹位于 Git 忽略的 `prototype/reports/private/`。
