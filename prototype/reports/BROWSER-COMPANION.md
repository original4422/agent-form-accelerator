## 实现及边界

- `browser-companion.mjs` 启动独立 Chromium 资料目录，仅控制最初 Page；默认保留本项目 `.profiles/companion`，临时模式退出删除。资料文件必须是明确指定的 Markdown，先检查解析限制再打开浏览器。
- `browser-controller.mjs` 在 `127.0.0.1` 随机端口提供固定操作集，无 CDP 网络监听、任意脚本、导航或提交接口。每次连接有随机 256 位令牌，跨客户端串行处理，执行前核对页面 URL；深层字段语义保护复用原后端。
- `browser-bindings-mcp.mjs` 复用四个来源绑定工具，启用上下文预取、批量发现、条件/独立分组、原生选项压缩；完整回执默认不变。先进能力来自既有后端，没有另造填写引擎；原型仍从 bench 目录导入通用后端，该模块没有样本答案。
- 启动失败、启动中断、关页、关浏览器和 Ctrl+C 清理连接文件并撤销端口。持久资料保留，临时资料删除。连接文件 0600，运行/资料目录 0700，终端命令不含令牌；源文档由 MCP 读取，遵循当前 Codex 的正常资料处理流程。
- 本次登录保留检查只证明虚构 Cookie 能在独立 profile 重启后保留，不证明 OAuth、验证码或任意招聘网站登录成功。真实页面可能自动保存输入；公开页虚构数据实验仍须先冻结网络。
- 本次手工检查的连接命令不改 Codex 审批设置；实际自动测试沿用既有 driver 的隔离临时配置和 `--approve-for-me`。交互时延不能由此单次自动任务外推。

## 验证

`node prototype/bench/companion-check.mjs` 最终 11/11 通过，结果见 [companion-checks.json](companion-checks.json)：无效输入预检、私有连接文件、错误令牌/Origin/Host 拒绝、类型/体积限制、跨 chunk UTF-8、真实 stdio MCP 填写、旧 URL 与标签页隔离、关页清理、测试 Cookie 持久化、启动取消、显式 URL 和 demo 两个 CLI 的 SIGINT 清理。

初次两个检查失败保留在 [companion-initial-failure.json](companion-initial-failure.json)。空文档报错改为清楚的中文；Host 检查的首次失败来自测试客户端：Node 26.8.1 的 fetch 忽略自定义 Host，实际仍发正确的 loopback Host，服务端返回 200 合理。改用 node:http 构造请求后，错误 Host 确实返回 403。此经验仅在该运行环境实测，不能泛化所有 fetch 版本。安全边界测试应确认实际发送的请求，不能只检查客户端传入参数。

按 security-auditor Skill 复查本次新增连接路径：未发现尚未处理的严重/高风险连接缺口；检查范围仅限新增代码及复用边界，不是整个依赖树或浏览器的全面安全认证。同一操作系统用户可读私有文件，不在此令牌机制的隔离范围内；未运行依赖升级，也没有改动全局 Skill。上述 Host 测试经验已留存于本报告；项目 Skill 维护规则不覆盖该全局 Skill，不提出无关的项目 Skill 修改。
