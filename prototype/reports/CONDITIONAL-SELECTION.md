# 条件选择：把搜索后的确定性决定前移

2026-09-21；Codex CLI 0.155.1；批次 `1789956240788`。

在含英文别名、同校不同校区、异步搜索和两段教育经历的独立 React Select 表单上，**现有批量搜索+填写 → 单次条件计划，完整 Codex 中位耗时 47.32 → 30.53 秒，减少约 35.5%（1.55×）。三组配对都更快，6/6 全部正确，无失败恢复。**

这是本地真实组件任务，不是实际招聘厂商服务器或完整申请验证。来源有明确的英文校名和校区，不能外推成任意中文学校翻译能力、任意网站或两倍稳定收益。

## 为什么换这个实验

上一轮定位到浏览器执行仅约2.3秒，多数等待发生在宿主阶段。精简成功回执只能影响尾部阅读；本轮优先检验可以省掉一次真实宿主往返的方案。

原流程：Codex提搜索词 → 批量发现三个选项列表 → Codex匹配学校/校区 → 调用填写。

条件流程：Codex一次给出来源绑定、搜索词和名称/校区词组 → 本地搜索 → 每项均唯一匹配才填写并回读。无法预先决定、歧义或条件不满足时，将实际候选交回Codex。没有要求模型提前声称选项存在。

## 时间边界

计时从实际Codex进程启动到退出，包括MCP启动/预取、宿主处理、全部工具调用、最终报告；排除初次浏览器加载、重置与预检。临时会话使用已有登录和默认模型配置，没有新增API Key；实际模型解析版本没有从事件获得，不编造模型名称。

`--approve-for-me`、shell/web禁用、临时MCP和其他CLI设置保持相同，未关闭审查或改变权限。所有原始尝试保留，无剔除失败或选最好一次。

条件计划的首次规划更长，但整个任务更短；单看首次工具调用或某次浏览器执行容易得出错误判断。各分段中位不能相加当总中位。时间戳定位不能将宿主残差全部归因于模型推理或自动审查。

## 实现与失败边界

- `conditional-choice.mjs`：按NFKC、大小写、Unicode词边界做字面词组匹配。所有labelParts必须同时出现，不提供模糊匹配、任意脚本或正则。返回结果截断时不能推定唯一。
- `document-session.mjs`：验证所有查询的来源/字段后批量发现。全部条件唯一满足，再将结果转成普通optionRef并走原apply路径。来源在发现后重新校验；实际选择重查查询、字段身份和唯一完整标签。
- 发现阶段失败不写普通来源事实、不展开经历；返回完整候选及可用optionRefs，允许宿主决定后恢复。若发现成功后页面再次变化，原执行器仍可能产生部分已完成项并返回complete=false；不承诺事务回滚。
- 全部原始evidence/observation/coverage保留；额外返回条件与实际匹配标签。complete仅为requested-targets，资料缺失不编造。
- 默认模式未变，条件能力仅通过隔离Playwright provider的 `AFA_SELECTION_MODE=conditional` 开放；显式form_search继续保留。

11项条件选择检查通过：词边界/规范化、截断/禁用/歧义、整套单次填写、缺少限定词回退并从候选恢复、错误限定词、重名、未知来源在搜索前拒绝、查询中源变更、查询中字段改义、发现后选项消失，以及普通模式拒绝新覆写。另两套真实stdio/MCP接入+实际组件状态检查通过。

第一遍检查中，普通模式确实拒绝了条件对象，但测试误期待`CHOICE_NOT_OBSERVED`而实际为`INVALID_OPTION_REFERENCE`。仅修正断言，初始记录保留在 `conditional-check-initial-assertion-failure.json`；没有把这次断言失败隐藏成首轮全绿。
