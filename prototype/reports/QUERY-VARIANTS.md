# 有界查询变体：保持选择条件，减少空结果恢复往返

日期：2026-09-21。前轮浏览器入口的实际 Codex 任务先搜“杭州”无结果，再改为 Hangzhou，产生第二次宿主调用。本轮检验能否把这种机械恢复预先放进计划。

## 协议

开启实验开关后，单个条件支持 `search: {queries: ["大阪", "Osaka"], labelParts: ["Osaka", "Japan"]}`。原来的单个 `query` 仍支持。每项最多三个不同词，所有计划最多十二个检索词，共享八秒发现预算。预算是浏览器动作遵守的期限，不是操作系统级强制中断或整个任务的时限。

模型负责从资料提出名称/翻译/别名，以及一套固定的目标名称和地区/校区条件。执行器没有翻译表、推理模型或样本答案。只在正常观察到零候选时尝试下一个词；非空但不符条件、歧义、禁用、结果截断和未就绪都不能自动切换。成功项不参加后续发现轮次。重试全程保持原 labelParts，不允许改变事实或删除限定词。

发现轮次后检查来源和原页面/字段语义，选中仍通过既有来源绑定、optionRef、重新查询唯一标签及最终回读。普通批次须所有条件成功才写；显式独立分组可保留失败项并完成其他组。重复组仍使用已观察的模板。本地搜索轮数不等于宿主工具调用数。

当前实验仅由隔离 Playwright provider 的 `AFA_QUERY_VARIANTS=1` 开启，需同时使用 conditional/independent 选择模式。浏览器 companion 和旧扩展默认未开启；尚不因一个新样本就升级默认协议。

## 验证范围

- 新增 11 项检查：输入/预算限制、遇歧义/冲突/禁用/截断/加载失败停止、真实组件空查询后的单次填写、校区不变、全空与独立组待办、来源漂移、字段改义、文档替换、全部普通来源预检、未开启拒绝。
- 原条件 11 项和独立分组 14 项回归通过。
- 两个新增目录页面共四次真实 stdio MCP 检查：开启时各一次 apply 完成五个目标，未开启时 variants schema 被拒绝且无输入。页面分别互换大阪和苏州的中/英文检索规则，苏州保留江苏/安徽同音名干扰，缺失到岗日期留空；应用状态独立检查。
- 这些是独立 React Select 组件与人工变化的检索规则，不是招聘网站克隆或真实目录的频率样本。资料明确提供双语名称，不能据此证明任意中文简历翻译能力。

## Codex 实验约定

两组交替配对：页面 A 旧→新，页面 B 新→旧。每个组合只跑一次并保留全部恢复；同一来源、页面、提示、现有登录、权限及宿主 driver。旧接口自由选择查询词，也能使用批量 form_search，不强制它先失败。新接口只增加查询变体 schema 和说明。计时包含 Codex 启动至退出，排除浏览器预加载和预检。

两页具有相同可见字段与候选标签，但目录查询索引语言相反。这是有意制造检索不确定性的小实验，结果只用于判断是否值得扩大测试。成功门槛是五个已知目标及真实选中实体正确、缺失日期留空并报告、零提交；还记录是否实际使用变体、候选歧义与完整耗时。源码/依赖/生成 bundle 共 139 项在测前记录指纹，测后再核对。

完整招聘流程、多页、上传、服务器接受及稳定两倍提速仍未证明。
