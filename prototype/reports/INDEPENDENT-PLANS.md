# 独立分组：把可确定的局部失败恢复留在执行器

2026-09-21。只测 Codex，沿用现有登录与权限机制。

## 要验证的问题

上一轮真实 Greenhouse 测试中，第一次请求发现 4 项离线查询不可用，第二次请求只是在已知证据上筛出 10 个可执行目标。新实验让 Codex 提前声明独立分组，检查是否可以在同一请求内完成这一步恢复，而不弱化匹配条件或丢掉未完成事项。

这符合之前耗时分解得到的优先级：浏览器局部执行已经较短，省掉一次宿主决定可能比继续省动作毫秒更有效。若新增分组规划和回执阅读抵消节约，实际总时间也可能不降，必须对照测量。

## 实现

实验开关 `AFA_SELECTION_MODE=independent`，可选参数：

```json
{
  "bindings": {"nameRef":"s1","countryRef":"s2","phoneRef":"s3","schoolRef":"s4","degreeRef":"s5"},
  "independentGroups": [["nameRef"],["countryRef","phoneRef"],["schoolRef","degreeRef"]]
}
```

上面仅解释分组；真实请求必须使用实际观察的 refs/sourceIds、url 和来源支持的 choices。分组必须覆盖每个顶层绑定且恰好一次。某组选项无法唯一确定时，该组全部暂缓；其余组沿用原有执行与校验。整个请求仍 `complete:false`，独立返回已执行子集状态和未完成目标。

`task` 保存本会话曾明确计划的来源目标，控件隐藏后仍保留。当前快照 `coverage` 保持原来“可见必填项”的含义，两者不会互相替代。全部暂缓时没有普通事实写入；来源、页面身份、含义变化或未知执行错误仍停止。分组没有事务回滚保证；具体边界见 ADR-0012。

## 正确性检查

- `independent-check.mjs`：14 项通过；首次失败只是错误码断言过窄，实际在写入前已拒绝含义变化，保存于 `independent-initial-failure.json`，之后扩充断言接受相应完整性错误。
- `independent-provider-check.mjs`：真实 Greenhouse 单次 stdio/MCP apply，10 项经独立 DOM oracle 核验，城市/学校/学历/专业 4 项未完成，刷新仍保留，零提交。
- 原条件计划 11 项、两套实际 MCP、文档绑定 8 项、复选集合 21 项与其实际公开页 MCP 检查通过。默认 all-or-return 行为保留。
- 代码复查发现需要在搜索更新 observation 时同步清除被替换文档的旧记录，已在计时前处理，并在文档替换检查中增加断言后重跑相关检查。

## 计时协议

驱动 `codex-independent.mjs`，三组交替顺序：旧/新、新/旧、旧/新。相同 Greenhouse URL、14 项虚构资料、提示、浏览器后端、Codex 权限及 10 项独立 DOM 检查；两边都预取上下文。浏览器公开页加载与 metadata preflight 不计时，Codex 启动、模型、工具调度/审查、执行、失败恢复、最终回复和退出全部计时。

页面加载只允许 GET/HEAD，输入前冻结全部网络。相同的 4 项远程查询有意保持不可用；不把它们删出资料或提示。比较的是这个相同的部分填写任务，不是完整申请、服务器接受或在线搜索速度。每次都检查最终文字报告所有 4 项未完成以及隐私/附件缺口。

源码在计时前冻结，清单 `source-hashes-independent-measured.json`。所有宿主尝试保留独立时间戳结果；不拿上一轮单次 55.77 秒直接作新结果的分母。

## 实测结果

批次 `1789959368271`，单位秒：

| 配对 | 原条件计划 | 独立分组 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 1 | 71.42 | 42.95 | 39.9% |
| 2（反向顺序） | 50.15 | 50.09 | 0.1% |
| 3 | 128.16 | 43.78 | 65.8% |
| 中位数 | 71.42 | 43.78 | 38.7% |

6/6 实际页面结果正确，60 个目标通过独立 DOM oracle，零提交。每次均提供全部 14 项事实，计划 7 个条件搜索，最终 10 项填入、4 项未完成。原计划每次两次工具调用，新计划每次一次；三个新计划均正确把国家/电话放在同组，把学校/学历/专业放在同组。六份上下文数据 hash 与提示 hash 分别完全一致。

**这不是稳定 38.7% 提速的证明。** 第二对基本持平；第三对旧流程首次工具调用前就用了 73.84 秒，主要长尾发生在执行器之外，没有证据能把它归因于此协议。没有剔除该长尾，也不将这组 2.9× 比值作为宣传结论。小样本更可靠的证据是：机械恢复从两次调用变成一次，正确性及未完成事项报告在这六次任务中保持。

本地执行时间中位约 7.09→7.04 秒，基本不变；第一次工具调用前中位 29.93→19.19 秒，但存在明显宿主波动。最后工具完成到进程结束的中位反而从 8.84→12.44 秒。新回执增加持久任务信息，可能影响尾部处理，但本实验没有隔离这个因素，不能把相关性写成因果结论。

## 报告判定修正

原检查只用 `/city|城市/` 匹配城市缺口，三份新模式回复写的是 “Location”，被误判遗漏，因此驱动最终退出码为 1。六个 Codex 子进程全部退出 0，六个页面 oracle、相同目标数和持久记录检查均通过。逐份复核最终文字后确认：四项未完成事实及隐私/简历缺口全部报告，没有声称申请完成。

原始 JSON 的 false 标志不改写。另存 `codex-independent-summary.json` 记录文字复核与修正原因；计时全部结束后才扩大关键词匹配，旧驱动归档到 `source-snapshots/independent-measured/codex-independent.mjs`。119 个源文件及依赖指纹按归档映射全部一致，运行时、提示和实际任务行为没有测后修改。原始私有日志仍保存在忽略提交的 private 目录。

## 下一步

独立分组已解决这类可预先界定的失败恢复，不再围绕同一场景反复加样本追求倍数。完整目标仍未达成：本实验主动阻断在线查询、文件和提交，不代表真实申请全流程。

接下来可检验保留完整本地验证与持久任务记录、仅精简发给宿主的成功回执是否减少尾部负担；同时优先考虑将已验证能力接入可实际试用的流程。不要为了更小 JSON 隐藏未完成项、候选歧义或验证失败，也不要把单次调用本身当成最终产品目标。
