# ADR-0005：把任务接口与浏览器动作后端分开

## 状态

Accepted for experiment，2026-09-21。基于 BACKEND-SUBSTITUTION.md 的受控替换实验；不是立即迁移日常浏览器或发布产品。

## 决策

1. 复用 `serveBindings` 提供相同的来源绑定、上下文和重复组接口。宿主负责首次语义匹配，本地有界循环负责已明确的机械步骤、等待与验证。
2. 浏览器动作后端允许替换。保留现有扩展路径及已验证行为；新增的 Playwright 后端作为强对照和后续组件兼容性实验入口，不让模型每次重新写控件脚本。
3. 不再把“自研点击/输入比 Playwright 快”作为项目核心假设。要证明的是完整用户任务中更少的模型生成、更少往返和更少恢复，而不是只测事件派发的毫秒。
4. Playwright 后端当前共享观察器与目标协调器。这是隔离动作层变量的设计，不是独立端到端竞品。研究结论仅限于动作后端可替换，不能据此否定或证明共享语义层的全部价值。

## 下一项应增加什么证据

停止反复增加相同 React/Radix 表单上的速度样本。增加独立实现的输入型搜索建议控件和更贴近招聘流程的任务，确认何时能本地选择、何时需要新语义判断，以及成功证据是否覆盖真实应用状态。对尚无明确选择/完成信号的控件，继续返回不支持或待判断；不能把填入字符串等同于选中合法实体。

## 取舍

扩展在用户点击授予的 activeTab 上运行；当前 Playwright 测量使用隔离浏览器 CDP。相近的测量速度不代表两者的安装、权限和日常会话复用成本相同。最终部署方式仍需实际试用证据。本轮不改变全局配置或已安装 Skill。
