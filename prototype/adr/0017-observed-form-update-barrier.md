# ADR-0017：已观察到的服务器更新构成批内等待边界

状态：接受为受限实验实现，2026-09-21。成功响应形态仅在本地受控协议中验证，真实 Ashby 只验证失败路径。

真实页面选中地点后，ApiSetFormValue 被冻结拦截，但 DOM 保留选择。进一步复查发现普通姓名输入也有同一依赖。仅增加批量大小会越过未完成的更新，并可能按旧题目继续填写；因此减少模型往返必须保留状态边界。

Playwright backend 被动观察已发出的同源、主 frame、固定路径/operation/mutation 请求，不直接调用 API。请求完成后检查 HTTP/JSON/GraphQL/已请求 FormRender 的受限形态；失败、未知或校验错误不能宣称完成。只保留计数和固定原因，不向模型输出请求变量、响应中的字段定义或错误原文。模型仍从公开 DOM 获取题目和候选。

工具内部每次已观察更新最多等待1.5秒，且不超过现有8秒目标预算。请求结束后等待120ms DOM 安静窗口，再核对公开语义；期间跟进同一操作的新增请求。题目、类型、必填、选项或说明改变返回 SERVER_FORM_CHANGED。相同含义的重新渲染沿用既有受限恢复。没有已观察更新时不增加此等待。

失败在同一 document 内保留，context 刷新、相同值或重新调用 apply 都不能消除失败，已验证台账失效。不自动重发写请求；新文档导航才重置跟踪器。新题目返回给模型后，可基于新观察决定下一份计划。

这不是通用请求依赖推断：未知接口、安装前的请求、任意延迟启动/渲染没有完整保证；120ms 是有界观察窗口，不是未来无变化的证明。真实成功响应尚未采样，未知/空形态保守停止。没有新增地点/附件支持，也没有完整申请或速度倍数结论。

实现与原始反例见 [FORM-UPDATES.md](../reports/FORM-UPDATES.md)。下一步需要拥有控制权的在线表单来验证服务器状态、动态分支和完整任务；真实招聘页继续只做冻结诊断，不能为凑成功结果发送虚构申请资料。
