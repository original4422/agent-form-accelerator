# ADR-0011：将可判定的选项条件放进同一次填写计划

状态：可选实验；2026-09-21。`AFA_SELECTION_MODE=conditional` 仅在隔离 Playwright provider 接通；默认仍要求显式观察选项。

## 设计问题

当来源已经确定机构名称与校区，模型是否必须在输入搜索词之后再回来选择一次？原接口即使批量搜索，仍通常是两个宿主工具回合：form_search → 模型阅读候选 → form_apply_bindings。

新增条件选择并不提前声称某个选项存在。它表达：先用来源支持的查询搜索，只有某个实际观察到的选项满足全部名称/限定词时才选它，否则返回候选给宿主。这将可以预先表达的决定移到第一次计划，保留不可预先判定的情况给模型。

## 接口与边界

`choices[ref] = {search: {query, labelParts}}` 也可出现在 repeatGroups.choices。来源仍由同一 ref 对应的 bindings[sourceId] 提供；字段必须在之前的观察里存在且支持搜索。

- query 长度上限120；labelParts为1–6个、各最多120字符的字面词组。
- 对完整标签和各词组做NFKC/大小写规范化，按Unicode字母/数字切词，忽略分隔标点；要求每个词组作为连续完整词出现。没有正则、脚本、模糊相似度或“第一个结果”。中文文字不做分词/语义翻译，翻译仍由宿主依据事实表达。
- 复用现有最多12项的批量 discovery。所有计划条件必须在非截断的实际结果中匹配恰好一个可用项，然后才写入来源事实。未知、歧义、截断、禁用或语义漂移均回退到完整候选，不自动删限定词或换更宽的条件。
- 解析结果转换成现有 optionRef，绑定到同一来源、字段语义与原查询。实际 apply 复查来源文件、字段与页面身份；autocomplete 重新执行原查询，核对唯一精确可见标签和选中状态。
- 首轮无匹配时，搜索框可能短暂输入查询，但不写普通事实、不展开经历。返回的 optionRefs 可以供宿主纠正后继续；未调用新的模型API。
- discovery后到实际写入期间仍可能发生变化。原执行器允许已验证的部分结果并明确 complete=false，这不是事务式回滚承诺。
- 返回完整 evidence/observation/coverage。缺失必填事实继续留空并报告，complete仍只表示请求目标，绝不提交。

## 事实与匹配不是同一件事

查询与条件是来源支持的意图，并非新增事实。模型须保留来源中全部相关限定词；本地程序能证实“唯一观察项满足所列字面条件”，不能证实模型翻译或语义理解一定正确。若来源未能提供足够限定词，应先显式搜索再让宿主决定。返回原始实际标签供检查。

旧的字符串或optionRef覆写规则不变。默认模式没有新schema分支，直接发送search条件仍被拒绝。显式form_search继续可用，避免把新模式变成不可恢复的单次尝试。

## 验证

来源为未映射中文Markdown，包含学校英文名、校区以及一个需翻译的城市；不能把该实验当成任意学校翻译能力证明。独立React Select控件包含同校两个校区、450ms异步返回和重复教育经历，oracle核验真实组件实体ID、选中标签、查询清空、10个来源目标、一个资料缺失日期和零提交。

测试和完整Codex对照见 `../reports/CONDITIONAL-SELECTION.md`。测量冻结实现、保留强批量观察基线、相同宿主权限与来源；不因减少一次工具调用就预先宣布提速。
