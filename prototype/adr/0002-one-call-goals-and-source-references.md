# ADR-0002：一次目标调用与资料引用

## 状态

Accepted for experiment，2026-09-21。用户已授权持续调研、实验和迭代，目标仍是完整任务明显提速且正确率不降低；本条不是正式产品接口承诺。

## 问题

有界阶段计划仍需 Codex 初始观察、生成阶段及最后观察。工具调用从 4 降至 3 只取得约两成收益。新的时间线还显示大段参数生成占据关键路径。

## 两个独立干预

1. `form_apply_goal`：提交明确字段目标，扩展内部观察、批量填写、等待依赖和校验。相同含义/类型的节点替换在有限次数内重绑；新语义、歧义、拒绝值返回宿主。来源仍是用户事实，不能凭标签猜个人信息。
2. 显式本地 JSON 资料引用：`form_apply_source` 仅传来源 ID，实际字段值通过本地进程送到同一个目标执行器。只允许启动时指定的文件；文件变化后拒绝使用旧会话。没有任意路径参数或永久个人资料数据库。

资料引用实验的前提是已经结构化且完成字段映射的事实。不得把简历抽取、陌生网站字段匹配或初次建档的成本隐藏掉。当前实现作为可测原型，不强制用户维护手工资料库。

## 对照要求

一次调用实验：脚本组也允许自己观察 DOM 并利用返回值核验，不强制前后多调用一次工具。最后局部核验两组都保留 120 ms 窗口；独立页面事件状态 oracle 继续保留。

资料引用实验：inline、来源 ID、引用同一份 facts 的脚本三组；每组获得相同事实内容。JSON 序列化和写入耗时计入，简历抽取不在范围内。不能将相对 inline 的结果宣称为相对所有浏览器脚本的结果。

## 边界

确切 group/label 已知时才能直接自动匹配；未知标签和自定义组件仍可能要求宿主判断。最终值验证不等于服务器接受，也不能保证任意延迟的变化。目标执行有总预算、每字段重试次数和回合数限制，已正确的字段不重复触发事件。

动态字段元数据随工具发现预取是后续候选：可能免去初始观察回合，但需要处理快照新鲜度、工具缓存失效和页面内容的信任边界。本轮不把这个假设算作已经实现。
